# 论文深度审查报告

## 审查结论
当前版本**不建议直接送审/送答辩**。论文选题有现实价值，主线也比较完整，第二章到第四章形成了“少样本域适应 - 目标域不可见域泛化 - 国产芯片部署”的连续叙事；但现阶段仍有 3 个 `major` 问题会直接影响结果可信度与结论边界，另有 3 个 `moderate` 问题和 1 个 `minor` 问题需要在提交前补齐。

本次审查基于源码与编译日志人工完成。由于当前环境不可用 `uv/python`，未执行 `paper-audit` 自带脚本，以下问题均来自对 `thesis.tex`、各章节源文件和 `thesis.log` 的逐段核对。

## 问题清单

### 1. Major: 第二章评测协议存在目标域训练/测试重叠，`Target Only` 上界不成立
- 位置：`data/chap02.tex:366-368`，`data/chap02.tex:493-494`
- 证据：
  - “all”场景表示使用目标域全部1345张无标签实测图像参与训练。
  - 所有场景下的测试集均保持一致，统一使用全部1345张实测SAR图像进行评估。
  - `Target Only` 又被定义为直接使用目标域带标签的实测SAR图像训练 ResNet50。
- 问题：这意味着第二章至少在 `all` 场景下默认采用了**目标域训练样本与测试样本重叠**的协议；而 `Target Only` 基线更进一步使用了**同一批目标域样本的标签**进行训练。若这是 transductive UDA 设定，论文必须明确声明；若不是，则会被审稿人直接视为训练/测试污染。
- 影响：`Target Only` 的“上界”不再是标准 hold-out 上界，`1-shot/3-shot/5-shot/10-shot` 的比较也会因为 seen target samples 混入测试集而被质疑。
- 建议：
  - 最稳妥的修法是重新构建**互斥的目标域 train/test split**。
  - 若坚持 transductive 设定，必须明确写出“训练阶段可访问测试输入但不可访问测试标签”，并把 `Target Only` 改成**仅在未见测试样本上评估**。

### 2. Major: 第四章“原模型”精度与第二、三章主结果不一致
- 位置：`data/chap02.tex:529`，`data/chap03.tex:439`，`data/chap04.tex:510`，`data/chap04.tex:593-633`
- 证据：
  - 第二章主结果：本章方法在 SAMPLE 上为 `99.15 / 92.45 / 96.78 / 97.15 / 97.95`（all / 1-shot / 3-shot / 5-shot / 10-shot）。
  - 第三章主结果：本章方法在 SAMPLE 与 S2M-5 上为 `96.93 / 93.70`。
  - 第四章又说明部署分支“沿用第三章的数据集设置”，但表中 `ResNet50 FP16` 原模型变成了 `98.14 / 94.87`；第二章部署分支的原模型也变成了 `99.89 / 97.18 / 96.54 / 92.21`。
- 问题：如果第四章确实使用的是第二、三章训练得到的教师模型和同一测试协议，那么这些“原模型”数值不应与前文主结果发生如此明显的偏移。除非这里换了 checkpoint、换了预处理、换了评测脚本，或从“多次平均”改成了“单次部署实测”，否则读者很难判断这些差异来自部署链路还是来自实验口径变化。
- 影响：这会直接伤害第四章全部压缩结果的可解释性，也会让读者怀疑整篇论文的结果管理是否一致。
- 建议：
  - 对齐第二、三章与第四章的**模型版本、预处理、评测脚本、是否取平均、是否板端实测**。
  - 在表注或正文中显式说明“第四章原模型数字为何与前文不同”，否则必须统一为同一套基准数字。

### 3. Major: 域泛化章节把闭集未知域结果外推为“开放世界”结论，claim scope 过宽
- 位置：`data/abstract.tex:36-39`，`data/chap03.tex:10-15`，`data/chap05.tex:82-88`
- 证据：
  - 摘要写道：方法“为‘开放世界’中未知域偏移带来的性能衰退提供了应对策略”。
  - 第三章引言写道：域泛化“依托于更符合实际应用场景的‘开放世界’假设”。
  - 但第五章未来展望又明确承认：本文方法“均假设源域与目标域共享相同的类别空间”，开放集识别和部分域适应仍是未来工作。
- 问题：现有实验只支持**未知域、同类别空间、闭集识别**下的泛化能力，并不能推出开放世界条件下对未知类别或类别空间不一致场景的有效性。
- 影响：因为该表述出现在摘要和章节引言，一旦被抓住，会被认为是 central claim overclaim，而不是措辞小问题。
- 建议：
  - 将所有“开放世界”表述收缩为“目标域不可见的闭集未知域泛化”或“same-label-space unseen-domain generalization”。
  - 把开放集/部分域适应保留在未来工作中，不要写进已验证结论。

### 4. Moderate: 多分类任务仍沿用二分类 TP/TN 公式，形式定义不严谨
- 位置：`data/chap02.tex:331-343`，`data/chap03.tex:277-293`
- 证据：
  - 第二章将准确率写为 `Accuracy = (TP + TN)/(TP + TN + FP + FN) = N_correct / N_total`。
  - 第三章也沿用了同样的二分类展开，并直接给出 Macro F1 定义。
- 问题：本文实验是 10 类和 5 类识别问题。若不引入 one-vs-rest 下标或平均方式，`TN` 在多分类任务中并不是自然定义量；`N_correct = TP + TN` 这句话更只在二分类里成立。
- 影响：不至于推翻实验，但会损害公式和定义层面的严谨性，尤其在答辩或外审中容易被抓住。
- 建议：
  - 准确率统一改写为 `Accuracy = (1/N)\\sum_i \\mathbf{1}(\\hat y_i = y_i)`。
  - Macro F1 先定义每类 `Precision_c / Recall_c / F1_c`，再给出类别平均。

### 5. Moderate: 第三章对比协议混入作者自定义增强，公平性与归因边界不清
- 位置：`data/chap03.tex:404-410`
- 证据：
  - 论文写道，为了“确保公平性”，把 3.2.2 节提出的像素级数据增强方法与四种经典通用域泛化算法“有机结合”作为最终对比基准。
  - 同时，SAR 专用方法则“严格遵照原始文献的参数配置与最优骨干网络”。
- 问题：这会让对比对象变成“被你方法局部增强过的通用算法”与“原始 SAR 专用算法”的混合集合。这样虽然可能出于善意，但会模糊两个关键问题：
  - 通用算法原始版本到底有多强。
  - 你方法的提升到底来自共享的像素级增强，还是来自完整框架中后续的特征级/对抗学习设计。
- 影响：不是致命错误，但会让“公平性”说法不够自洽，也会削弱方法归因的清晰度。
- 建议：
  - 最好同时报告三类结果：原始 baselines、加像素增强的 baselines、完整方法。
  - 若版面有限，至少要解释为什么只改这四个 baseline，以及为什么 SAR 专用方法不作同等适配。

### 6. Moderate: 结果稳定性报告不足，小幅领先缺少方差信息支撑
- 位置：`data/chap03.tex:411-412`，`data/chap03.tex:418-440`，`data/chap02.tex:529`
- 证据：
  - 第三章明确写到：每种方法执行十次独立实验，并报告平均准确率与 Macro F1。
  - 但结果表只给了点估计，没有标准差、置信区间或显著性检验。
  - 第二章则直接给出单个准确率表，但没有说明是否重复实验。
- 问题：在你需要强调“优于先进算法”的地方，部分领先幅度只有 1-3 个百分点；没有方差信息时，读者无法判断这种领先是否稳健。
- 影响：这会削弱 SOTA claim、部署损失控制、以及“跨数据集稳定性”这几类关键结论的统计说服力。
- 建议：
  - 第三章至少补 `mean ± std`，最好加 paired t-test 或 bootstrap CI。
  - 第二章也建议补重复实验次数和方差，尤其是少样本场景更容易受随机抽样影响。

### 7. Minor: 编译日志仍有模板/版式告警，提交前应清理

- 证据：

- 影响：答辩版或最终提交版容易出现图表跨页、版心越界或环境依赖变化后的编译波动。
- 建议：
  - 清理 `subfig` 相关配置。
  - 处理第 701 行对应大图的尺寸或分页策略，并顺带清理 overfull/underfull 警告。

## 总体判断
论文的**研究选题、章节主线和工程落地意识是成立的**，这也是它最大的优点；但当前最需要优先处理的不是文字润色，而是：

1. 第二章评测协议要先自洽。
2. 第四章数值要和前文完全对齐。
3. “开放世界”相关 claims 必须收缩到实验真正支持的范围。

如果先把这三件事修正，再补上统计稳定性与对比公平性说明，这篇论文的整体可信度会明显提升。
